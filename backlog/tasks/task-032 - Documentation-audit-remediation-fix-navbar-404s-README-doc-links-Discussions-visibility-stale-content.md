## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A documentation audit (2026-07-08) found: (1) the docfx site's Docs navbar dropdown renders four dead links — the section headers in docs/toc.yml (Tutorial, How-to guides, Reference, Explanation) have no href, and the docfx modern template renders href-less dropdown children as links to /undefined → 404; (2) the README Documentation section lists ~20 repo-relative docs/*.md links that do not lead to the published site and render broken on the NuGet package page; (3) GitHub Discussions is enabled on the repo but mentioned nowhere (README, SUPPORT.md, issue-template config all route questions to Issues); (4) stale content: README beta banner references 0.2.0-beta.1 (current: 0.2.0-rc.1), docs/benchmarks.md headlines beta.1 figures, index.md references the old `Huml` facade name, root PLAN-documentation.md is a superseded planning doc describing files that no longer exist; (5) the companion huml-dotnet-examples repo is linked per-page in docs but has no landing presence on the site. Decision: keep docfx (deployed, CI green, generates API reference); fix the TOC rather than replace the system.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Root cause chain for the 404s: docfx modern template nav.ts loadNavItems does `new URL(i.href, navUrl)` for each first-level child of a navbar dropdown; when href is undefined this yields <site>/undefined. Confirmed against dotnet/docfx main. Any future first-level node added to docs/toc.yml MUST carry an href — a comment now records this in the file.

Kept docfx rather than switching documentation systems: the site, CI deploy (docs.yml via OIDC Pages), search, and generated API reference all work; the defect was two missing-href lines of TOC, not the toolchain. Replacing it would forfeit the xref-checked API reference for no gain.

PLAN-documentation.md at the repo root turned out to be deliberately gitignored (local-only planning doc), so it never reached GitHub — left on disk, dropped from the CHANGELOG entry. docs/api/*.yml are likewise untracked build artefacts regenerated by CI; the stale local copies are harmless.

Deployed and verified live: docs/how-to-guides.html, reference.html, explanation.html, examples.html all 200; live toc.json shows every Docs dropdown entry with a valid href. Examples-repo counterpart work tracked as TASK-033 (done).
<!-- SECTION:NOTES:END -->
